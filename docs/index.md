# Centralis Docs

Purpose: route maintainers to the authoritative documentation for this project.
Read this first when adding or looking for project documentation.
This page does not define product copy, implementation behavior, or deployment policy.

## Document Map

- [Documentation Policy](policy.md): rules for where project documents belong and how they should be maintained.
- [Contact Form Backends](reference/contact-form-backends.md): research notes for China-accessible and self-hosted ways to collect homepage contact form submissions.

## Document Classes

- `spec/`: normative truth, including contracts, invariants, schemas, and required behavior.
- `runbook/`: executable sequences, including setup, validation, release, migration, and troubleshooting procedures.
- `reference/`: descriptive current state and research notes that do not define correctness.
- `decisions/`: durable rationale for accepted tradeoffs and long-lived choices.

Create a class directory only when adding its first real document. Do not add empty folders.
