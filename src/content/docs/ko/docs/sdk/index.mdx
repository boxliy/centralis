프린터 SDK는 애플리케이션이 NIB 인쇄 기능에 접근하는 진입점입니다. SDK가 프린터 기능을 대신 “추측”하지는 않습니다. 이미 확인한 디바이스, 명령어 집합, 연결 방식을 여러 언어에서 일관된 인쇄 흐름으로 정리합니다.

먼저 이 사고 모델을 기억하세요.

```text
指令构建器 -> 脚本/字节 -> connected device -> 分片/流控写入 -> 可选状态读取
```

즉 템플릿 코드는 ESC, TSPL 또는 CPCL 바이트를 생성하는 일만 담당합니다. 연결 코드는 이미 연결된 디바이스 객체를 가져오고, 쓰기 파이프라인은 현재 전송 방식에 맞춰 바이트를 디바이스에 씁니다. 상태 읽기는 선택 기능이며, 디바이스, 명령어 집합, 연결 계층이 모두 지원할 때만 연동합니다.

## 선택 순서

패키지와 예제를 선택하기 전에, 비즈니스 사실을 기준으로 바깥에서 안쪽으로 네 가지를 먼저 확정하세요.

1. 프린터 Family: Boxliy, Aryten 또는 Lin8inch.
2. 명령어 계열: ESC, TSPL 또는 CPCL. 실제 장비 펌웨어 지원을 기준으로 합니다.
3. Transport: BLE, 클래식 블루투스, USB / WebUSB, 네트워크, 또는 미니프로그램 / 크로스엔드 프레임워크 브리지.
4. 언어 패키지: TypeScript, Dart, Java, Objective-C 또는 Swift.

이 순서는 흔한 오해를 피하게 해 줍니다. 특정 언어 예제를 따라 코드를 다 작성한 뒤에야 장비가 해당 명령어 계열이 아니거나, 현재 플랫폼에서 예제가 요구하는 BLE characteristic을 얻을 수 없다는 사실을 발견하는 경우가 많습니다.

## 언어 연동

| 언어 | 일반적인 실행 환경 | connected device 형태 | 문서 |
| --- | --- | --- | --- |
| TypeScript | Web, Node, 미니프로그램, Taro, UniApp, WebUSB | `ConnectedDevice`, `write()`, 선택적 `read()` / `notify()` 제공 | [TypeScript SDK](./typescript/) |
| Dart | Flutter, 모바일, 크로스플랫폼 클라이언트 | `ConnectedDevice<T>`, `write()`, `read()` stream, 연결 상태 제공 | [Dart SDK](./dart/) |
| Java | Android, JVM 도구, 네트워크 또는 블루투스 연동 | `Device`, `write()`, `read()`, `close()` 제공 | [Java SDK](./java/) |
| Objective-C | 기존 iOS 프로젝트, 혼합 언어 프로젝트 | `BNDevice`, `writeData:error:`, `readWithTimeout:error:` 제공 | [Objective-C SDK](./objective-c/) |
| Swift | iOS, macOS, CoreBluetooth | `NibDevice`, `write(_:)`, `read(maxLength:)` 제공 | [Swift SDK](./swift/) |
